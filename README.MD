Hospital API - Tarea 013
API REST de usuarios desarrollada con Node.js, Express 5, PostgreSQL 16.15 y Sequelize 6, como parte de la Tarea 013 de la clase 7 de Node.js.
Alcance actual: aunque el repositorio se llama hospital-api, esta entrega implementa el CRUD de usuarios pedido en la consigna. No incluye todavía módulos de pacientes, turnos u hospitales.

Tecnologías
- Node.js y Express 5: servidor y endpoints HTTP.
- PostgreSQL 16.15: persistencia relacional.
- Docker Compose: entorno local de base de datos.
- Sequelize 6 + pg: ORM y conexión con PostgreSQL.
- Yup: validación y normalización de datos mediante DTOs.
- dotenv y cors: configuración y acceso desde un frontend.
- pgAdmin 4 (opcional): administración visual de PostgreSQL.
Requisitos
- Node.js 20 o posterior y npm (desarrollado localmente con Node.js 24).
- Docker Desktop en ejecución.
- Un cliente de PostgreSQL como pgAdmin 4 (opcional, para crear e inspeccionar la tabla).
Inicio rápido
1. Clonar e instalar dependencias
git clone https://github.com/TU_USUARIO/hospital-api.git
cd hospital-api
npm install
Reemplazá TU_USUARIO por el usuario real de GitHub del repositorio.
2. Configurar variables de entorno
Si todavía no existe un archivo .env, crealo a partir de .env.example:
Copy-Item .env.example .env
Variables esperadas (valores locales de ejemplo):
PORT=3000
CORS_ORIGIN=http://localhost:5173
DB_HOST=127.0.0.1
DB_PORT=5433
DB_NAME=nodepgdb
DB_USER=postgres
DB_PASSWORD=CAMBIAR_POR_TU_PASSWORD_LOCAL
DB_LOGGING=false
Importante: el .env contiene tu contraseña real y no debe subirse a GitHub. La contraseña de .env tiene que coincidir con la del usuario de PostgreSQL. El puerto 5433 es el publicado en Windows para evitar un conflicto con otra instancia local de PostgreSQL.
3. Levantar PostgreSQL con Docker
Desde la raíz del proyecto:
docker compose up -d --wait
docker compose ps
La configuración local de docker-compose.yaml utiliza PostgreSQL 16.15 y el mapeo:
ports:
  - "5433:5432"
volumes:
  - ./postgres:/var/lib/postgresql/data
Esto significa: Windows/host 5433 -> contenedor 5432. La carpeta postgres/ conserva los datos aunque se detenga o recree el contenedor.
4. Crear la tabla users
Conectate en pgAdmin (o cualquier cliente SQL) con:
Campo	Valor
Host	127.0.0.1
Puerto	5433
Usuario	postgres
Contraseña	DB_PASSWORD de .env
Base de datos	nodepgdb


Abrí el Query Tool de la base nodepgdb y ejecutá:
CREATE TABLE IF NOT EXISTS users (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(120) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
Para cargar datos de ejemplo (opcional, solo una vez):
INSERT INTO users (name, email) VALUES
  ('John Doe', 'john.doe@example.com'),
  ('Jane Smith', 'jane.smith@example.com');

SELECT * FROM users ORDER BY id;
Si la tabla ya tiene esos emails, no vuelvas a ejecutar el INSERT: la restricción UNIQUE lo rechazará.

5. Iniciar la API
npm run dev
Salida esperada, si la base está disponible:
Database connection established -> nodepgdb
Server is running on http://localhost:3000
El comando utiliza el modo --watch de Node.js. Para iniciar sin watch:
npm start
Comprobá la API en http://localhost:3000/api/health. Respuesta esperada:
{ "status": "ok" }
Endpoints
Base URL: http://localhost:3000
Método	Ruta	Descripción	Respuesta exitosa
GET	/api/health	Estado del servidor	200
GET	/api/users	Listar usuarios por ID	200
GET	/api/users/search?keywords=ada	Buscar por nombre o email, sin distinguir mayúsculas	200
GET	/api/users/:id	Obtener usuario por ID	200
POST	/api/users	Crear usuario	201 y header Location
PATCH	/api/users/:id	Actualizar uno o más campos	200
DELETE	/api/users/:id	Eliminar usuario	204, sin body


Ejemplo: crear un usuario
POST /api/users con header Content-Type: application/json:
{
  "name": "Ada Lovelace",
  "email": "ada@example.com"
}
Ejemplo de respuesta exitosa (el ID real puede variar):
{
  "data": {
    "id": 3,
    "name": "Ada Lovelace",
    "email": "ada@example.com"
  }
}
El DTO de entrada aplica trim() al nombre y trim() + lowercase() al email. El DTO de salida expone solo id, name y email, no el modelo completo.
Errores esperados
Caso	Estado	Código
Datos inválidos o PATCH vacío	400	VALIDATION_ERROR
ID que no es entero positivo	400	INVALID_ID
JSON mal formado	400	INVALID_JSON
Usuario inexistente	404	USER_NOT_FOUND
Ruta inexistente	404	ROUTE_NOT_FOUND
Email duplicado	409	EMAIL_TAKEN
Error inesperado	500	INTERNAL_ERROR (o código específico)


Probar la API
Podés utilizar el navegador para los GET, o la extensión REST Client de VS Code con un archivo api.http (si está incluido en tu copia del proyecto). También podés usar PowerShell:
# Health
Invoke-RestMethod -Uri 'http://localhost:3000/api/health'

# Listar
Invoke-RestMethod -Uri 'http://localhost:3000/api/users'

# Crear
Invoke-RestMethod -Method Post `
  -Uri 'http://localhost:3000/api/users' `
  -ContentType 'application/json' `
  -Body '{"name":"Ada Lovelace","email":"ada@example.com"}'
Si ya creaste ada@example.com, el último ejemplo devuelve 409 por email duplicado: es una validación esperada.

Para verificar persistencia, creá un usuario, detené Node.js con Ctrl + C, ejecutá otra vez npm run dev y comprobá que sigue apareciendo en GET /api/users. También debería permanecer luego de docker compose down y docker compose up -d --wait, porque los datos se guardan en ./postgres/.

Para verificar el fail fast, detené primero Node.js, apagá la base con docker compose down e intentá iniciar la API. Debería fallar al conectar; al terminar, volvé a iniciar Docker y la API.

Solución de problemas
Mensaje / síntoma	Posible solución
password authentication failed desde pgAdmin	Verificá puerto 5433, usuario postgres y la contraseña real configurada en PostgreSQL. Cambiar .env no actualiza automáticamente una base ya inicializada.
relation "users" does not exist	Creá la tabla en la base nodepgdb del contenedor; verificá DB_NAME y DB_PORT=5433.
port is already allocated	Mantené 5433:5432 si ya usás 5432 en Windows.
Missing parameter name ... :/id	Corregí las rutas dinámicas en Express: deben escribirse /:id.
ECONNREFUSED	Revisá docker compose ps y que Docker Desktop esté iniciado.
El servidor no arranca	Revisá las variables del .env, la disponibilidad de PostgreSQL y los logs de Node.


Seguridad y Git
El archivo .gitignore debe incluir al menos:
node_modules/
.env
postgres/
Nunca subas credenciales reales ni archivos internos de la base. El archivo .env.example sí se versiona, pero con contraseñas ficticias. Si alguna credencial real llegó a publicarse, hay que cambiarla.
Detener el entorno
- API: Ctrl + C en la terminal de Node (el servidor cierra el pool de Sequelize).
- Base de datos: docker compose down.
- Para volver a iniciar: docker compose up -d --wait y después npm run dev.
